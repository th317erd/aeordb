## 1. Outcome

writer exists. Build bounded readers first, make capability/SystemFamily
admission fail before mutation, prove native platform durability support, and
only then permit exact writers that reproduce hand-authored bytes.

This child is complete when a worker unfamiliar with the decision conversation
can derive every legal byte and every malformed rejection from the checked-in
contract registry, fixtures, and reference implementation without calling a
production serializer.

## 4. Corrected Header and Control Contracts

The v4 DatabaseHeader has two independent 1,024-byte slots and data starts at
offset 2,048. Bytes 464 through 479 hold a random nonzero
`physical_instance_id`; bytes 480 through 1019 are reserved zero except the
CRC at 1020 through 1023. CRC-32/ISO-HDLC covers bytes 0 through 1019.

Copies preserve physical identity and are diagnostic/read-only while the
original may exist. Clone/restore adoption must hard-publish a new physical ID
and writer fence before independent writes.

System controls are protected ordinary FileRecords under:

```text
/.aeordb-system/controls/v1/
  <control-kind-4-lowercase-hex>/
  <blake3(identity)-64-lowercase-hex>/
  a.ctrl | b.ctrl | i.ctrl
```

Mutable controls use A/B. Immutable controls use `i.ctrl`. Payload identity is
repeated and revalidated, so a digest collision is corruption. Only
`ControlStore` may write the subtree. Generic file, sync, plugin, and index APIs
cannot mutate it.

## 5. P0b: Independent Reference and Fixtures

### Start Gate

- Child 08 has recorded baseline commit, inventory digests, route count, test
  count, intended divergences, and recent-fix ledger.
- The worktree's unrelated user changes are identified and preserved.
- Exact decision-log sections Rounds 10 through 15 are available.

### Work

1. Create `tools/v4-reference/` with no dependency on AeorDB production
   serializers, readers, hash helpers, or enum declarations.
2. Hand-author fixtures for hash widths 32 and 64. Include minimum, maximum,
   empty, linked, zero-optional, and every malformed class.
3. Freeze the expanded binary-owned SystemFamily Registry fixture and digest.
4. Freeze exact v4 header A/B selection, equal-sequence ambiguity, CRC failure,
   unknown capability, padding, and adoption fixtures.
5. Freeze all canonical value/config/path/glob/file-key/APOS encodings and test
   boundary integers, CRLF-related positions, invalid UTF-8, and platform paths.
6. Freeze cross-record formulas mechanically. At minimum recheck every
   `fixed + count * record` body with both hash widths and checked arithmetic.
7. Add mutation tooling that flips each field, bit, length, checksum, enum,
   reserve byte, identity component, and trailing byte independently.
8. Record fixture provenance and independent reviewer sign-off. A production
   codec author cannot approve their own generated bytes.

### Required Outputs

- `format-contract-registry.json`
- `format-fixture-manifest.json`
- fixture binaries and annotated hex
- reference encode/decode result ledger
- ASFR fixture and fingerprint
- collision/ID/capability registry report

### Exit Gate

`timeout 2m ./scripts/plan/check-v4-contracts.sh` proves formulas, unique IDs,
typed hash roles, fixture coverage, and absence of superseded assertions. No
fixture byte is produced solely by a production serializer.

## 6. P0c: Machine Contract Registry

The registry checker must fail when:

- EntryType, KV tag, artifact/control kind, capability bit, family ID, enum ID,
  route class, or config property collides outside an explicit scope;
- a format lacks identity, generation, body cap, checksum, malformed behavior,
  reserve-zero rule, or both hash-width fixtures;
- a hash field lacks one role: graph edge, identity, fingerprint, evidence, or
  hint;
- a dynamic record lacks discoverability and retention/compaction ownership;
- a hard transition lacks crash-before/crash-after behavior and one selector;
- an exact format lacks a bounded decoder/allocation rule;
- a SystemFamily or protected literal lacks exactly one selected policy; or
- a producer or consumer has no owner.

The registry is the generation source for Rust constants and architecture
tests only after the hand-authored source is green. Generated files contain a
digest of their registry input and must fail CI when stale.

## 7. P1a: Bounded Readers Before Writers

1. Implement v3/v4 header dispatch without rewriting either format on open.
2. Implement common bounded-reader primitives with checked arithmetic before
   per-kind readers.
3. Reject unknown required capabilities, versions, kinds, enum values,
   noncanonical order, identity mismatch, nonzero reserve, overflow,
   under/overlength body, trailing bytes, and checksum mismatch.
4. Parse large pages/records incrementally where the format permits; never
   allocate from an unvalidated length.
5. Keep v0/v3 readers and bytes stable. Add byte-for-byte reopen fixtures.
6. Add fuzz/mutation corpus execution with a per-case watchdog and allocation
   ceiling.

### Narrow Gate

```bash
timeout 5m cargo test -j 6 -p aeordb --test v4_format_fixture_spec
```

Expected green means every hand-authored valid fixture decodes identically and
the malformed corpus rejects with the frozen error class on Linux.

## 8. P1b: Capability and SystemFamily Admission

1. Decode selected DatabaseHeader capabilities before any writer, repair,
   plugin, peer, task, or migration activation.
2. Load and fingerprint the exact binary-owned SystemFamily registry.
3. Compare stored reader/writer floors, registry identity, and peer capability
   negotiation before mutation.
4. Unsupported required read capability opens only in the explicitly allowed
   diagnostic mode; unsupported write capability refuses before mutation.
5. Unknown protected state fails the affected operation closed and creates
   actionable diagnostics rather than defaulting to user data.
6. Add clone/copy tests proving unchanged physical IDs remain read-only until
   adoption publishes a new identity and writer fence.

## 9. P1c: Native Platform Probes and Read-Only Control Selection

Implement test-only publication probes and ControlStore reads for:

- Linux file/data barriers, parent-directory synchronization, durable replace,
  preallocation, and read-back;
- macOS equivalents and filesystem capability reporting;
- Windows native directory-handle flush, durable replace, file identity, and
  explicit unsupported results; and
- A/B control selection, torn slot fallback, equal-sequence ambiguity, identity
  collision, and immutable control verification.

`wyatt-mac` and `win11vm` run the same fixture manifest and malformed corpus.
Cross-compiled binaries do not clear this gate.

## 10. P3a Format-Owned Writer Slice

Writers begin only after P0/P1 are green and reviewed. Land in this order:

1. deterministic writer-to-fixture tests for common headers and primitive
   codecs;
2. v4 DatabaseHeader inactive-slot write, barrier, read-back, selection, and
   adoption path;
3. v1 entity and immutable artifact envelope writers;
4. ControlStore FileRecord writer using Child 02 durability and Child 03
   namespace/locator coordinators; and
5. writer capability activation only after every required reader exists.

Writer output must byte-match the independent fixtures. No generated golden is
accepted as proof. This slice does not activate a v4 namespace, index, GC, or
migration destination for service writes.

## 12. Rollback

- P0 is reference/test-only and can be reverted as one documentation fixture
  unit before writer activation.
- P1 readers remain unreachable from production writes and can be reverted
  without persisted-state changes.
- After a v4 capability or header is written, do not roll back to a binary that
  lacks the stored reader/writer floor. Disable activation or move state forward
  with a compatible reader.
- Never rewrite a fixture to match broken production output. Fix the writer or
  reopen the contract round.

- [ ] Both hash-width fixture sets are hand-authored and independently reviewed.

- [ ] Native Linux, macOS, and Windows fixture results match.
